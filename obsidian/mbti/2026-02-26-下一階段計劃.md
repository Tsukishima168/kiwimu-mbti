## 🟡 本週計劃（優先順序）

### A. LIFF 串接 shop.kiwimu.com（1–2 天）

**目標**：讓用戶可以從 LINE App 直接打開商店，並自動取得 LINE 身份

**步驟：**
1. LINE Developers Console → 建立 LIFF App
   - Endpoint URL：`https://shop.kiwimu.com`
   - Size：Full（全螢幕）
2. 取得 LIFF ID，加入 `.env.local`：
   ```
   NEXT_PUBLIC_LIFF_ID=your-liff-id
   ```
3. 安裝 LIFF SDK：
   ```bash
   npm install @line/liff
   ```
4. 建立 `lib/liff.ts`：
   ```typescript
   import liff from '@line/liff';

   export const initLiff = async () => {
     await liff.init({ liffId: process.env.NEXT_PUBLIC_LIFF_ID! });
     return liff;
   };

   export const getLiffProfile = async () => {
     const l = await initLiff();
     if (!l.isLoggedIn()) l.login();
     return l.getProfile(); // { userId, displayName, pictureUrl }
   };
   ```
5. 在 `app/layout.tsx` 偵測 LIFF 環境，自動導入 LINE profile
6. 將 LINE userId 與 Supabase 用戶帳號關聯（users 表新增 `line_user_id` 欄位）

**LINE Developers 設定位置：**
- https://developers.line.biz/ → Provider → Messaging API Channel → LIFF

### B. LINE Pay 整合（先建不開放）（2–3 天）

**目標**：建立完整 LINE Pay 流程，用 feature flag 控制是否顯示

**架構：**
```
用戶點「結帳」→ 檢查 LINE_PAY_ENABLED 環境變數
  ↓ false → 顯示「付款功能即將開放」
  ↓ true  → LINE Pay Request API → 取得 paymentUrl → 跳轉 LINE Pay
LINE Pay 付款完成 → Webhook → 確認訂單 → 更新 Supabase
```

**需要的檔案：**
```
app/api/linepay/
  ├── request/route.ts   ← 建立 LINE Pay 請求
  ├── confirm/route.ts   ← 確認付款（LINE Pay callback）
  └── cancel/route.ts    ← 取消處理
lib/linepay.ts           ← LINE Pay SDK 封裝
```

**環境變數（待拿到金流後填入）：**
```
LINE_PAY_CHANNEL_ID=
LINE_PAY_CHANNEL_SECRET=
LINE_PAY_ENV=sandbox  # 先用沙盒
LINE_PAY_ENABLED=false  # 上線前改為 true
```

**目前可做：**
- 建立所有 API routes（邏輯完整）
- 前端 UI 加入付款按鈕（feature flag 隱藏）
- 用 LINE Pay Sandbox 測試整個流程

### C. 自動化客服流程（ManyChat → N8N）（3–5 天）

**目標**：訂單詢問、預約確認、狀態查詢 — 全自動回應

**架構圖：**
```
LINE 用戶發訊息
    ↓
ManyChat（關鍵字觸發 / Flow）
    ↓ Webhook
N8N（邏輯處理節點）
    ├── 查詢 Supabase 訂單
    ├── 更新 Google Sheet
    ├── 觸發 LINE OA 回覆
    └── 發送通知給管理員
```

**ManyChat 需設定的 Flow：**
| 觸發關鍵字 | 動作 |
|-----------|------|
| 「查詢訂單」、「我的訂單」 | → Webhook → N8N 查 Supabase → 回傳訂單狀態 |
| 「預約」、「訂位」 | → 引導填表 or 直接跳轉 shop.kiwimu.com |
| 「取消」 | → 確認 → Webhook → N8N 更新狀態 |
| 「人工客服」 | → 轉接真人 |

**N8N Workflow 節點（每個獨立一個 workflow）：**
1. `訂單查詢 workflow`：接收 LINE userId → 查 Supabase → 格式化 → 回 ManyChat
2. `新訂單通知 workflow`：Supabase webhook 觸發 → 寫入 Google Sheet → 通知管理員
3. `訂單狀態更新 workflow`：管理員在 Google Sheet 改狀態 → N8N 偵測 → 通知用戶

### D. Google Sheets 訂單自動登記（1–2 天）

**目標**：每筆新訂單自動同步到 Google Sheet，人工填單 + 自動填單並存

**Google Sheet 欄位設計：**
| 欄位 | 來源 |
|------|------|
| 訂單編號 | Supabase auto-id |
| 訂單日期 | created_at |
| 客戶姓名 | users.name |
| LINE 暱稱 | line profile（如有串 LIFF）|
| 商品名稱 | order_items |
| 數量 | order_items.quantity |
| 金額 | total_amount |
| 付款方式 | LINE Pay / 到店 |
| 狀態 | pending / confirmed / cancelled |
| 備註 | 人工填寫 |

**N8N 連線方式：**
```
Supabase Trigger（新 row 插入 orders 表）
    ↓
N8N → Google Sheets node → Append Row
    ↓
LINE OA → 通知管理員「新訂單 #xxx」
```

**人工填單保留**：Google Sheet 最後幾欄（備註、確認人、特殊備注）保留人工填寫空間
