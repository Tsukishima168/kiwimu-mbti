# 📓 2026-02-28 OAuth 轉址修復日誌 (Subdomain Migration)

> **專案**：Kiwimu MBTI Lab / Subdomain Migration
> **處理人**：Tech Lead (AI Assistant)
> **日期**：2026-02-28
> **狀態**：✅ 已修復並驗證

---

## 🚩 問題描述
在將 MBTI Lab 從 `kiwimu-mbti.vercel.app` 遷移至主網域 `kiwimu.com` 後，用戶反應 Google 與 LINE 登入失效。
*   **Google 報錯**：`400: redirect_uri_mismatch`
*   **LINE 報錯**：`400 Bad Request` (Invalid redirect_uri)

## 🔍 原因分析
雖然程式碼（`.env` 與 `Login.tsx`）已將轉址路徑更新為新網域，但各家 **OAuth Provider Console** 的白名單尚未同步更新「新家地址」，導致安全性檢查不通過而攔截要求。

## 🛠️ 修復方案 (SOP)

### 1. LINE Login (LINE Developers Console)
*   **調整位置**：`LINE Login` -> `Callback URL`
*   **新增路徑**：`https://kiwimu.com/callback`
*   **注意**：需保留舊有的 localhost 或 vercel 測試路徑，採「換行新增」方式。

### 2. Google OAuth & Firebase (Google Cloud Console)
*   **調整位置**：`APIs & Services` -> `Credentials` -> `OAuth 2.0 Client IDs` (Web Client)
*   **Authorized JavaScript origins**：加入 `https://kiwimu.com`
*   **Authorized redirect URIs**：需包含以下關鍵路徑（Firebase 代理）：
    *   `https://kiwimu-mbti.firebaseapp.com/__/auth/handler`
    *   `https://kiwimu.com/__/auth/handler`
    *   **進階相容建議**：同時加入結尾包含 `/` 的版本（例：`.../handler/`）。

### 3. Firebase Authentication (Firebase Console)
*   **調整位置**：`Authentication` -> `Settings` -> `Authorized domains`
*   **新增網域**：`kiwimu.com`
*   *備註：若未加入，Firebase 會直接在發起請求前報錯。*

### 4. Supabase Auth (Supabase Dashboard)
*   **調整位置**：`Authentication` -> `URL Configuration`
*   **Site URL / Redirect URLs**：加入 `https://kiwimu.com/**`
*   **目的**：確保 `syncGoogleToSupabase` 能正確執行，並存入跨子網域共享的 `.kiwimu.com` Cookie。

---

## 🎓 交接重點：資料流向說明
*   **Firebase (Firestore)**：測驗過程、即時進度、原始測驗結果的主資料庫。
*   **Supabase (PostgreSQL)**：**最終用戶資料中心**。透過 `userDataCollector.ts` 的雙寫機制（Fire-and-forget），將行為統計、MBTI 分群標籤同步至此。
*   **Bridge 機制**：登入時必定觸發 Firebase → Supabase 同步，確保子網域（passport / shop / map）能讀取到一致的用戶 Profile。
