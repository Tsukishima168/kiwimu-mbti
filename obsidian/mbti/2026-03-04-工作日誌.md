### 任務 1: 訂單系統 RLS 修復

**問題描述**
- 用戶提交訂單時收到錯誤: `訂單失敗：建立訂單失敗，請稍後嘗試`
- 後台錯誤: `ERROR: 42710: policy already exists`

**診斷過程**
1. 檢查 API 端點: `/api/order/route.ts` ✅ 正常
2. 檢查 Supabase 連接: ✅ 配置正確
3. 識別問題: RLS (Row Level Security) 政策配置不正確
   - 舊政策: `"允許建立訂單"` 只允許特定角色
   - 新要求: 允許匿名用戶提交訂單

**解決方案**
執行 SQL 腳本 [FIX_RLS_ORDERS.sql](./scripts/FIX_RLS_ORDERS.sql):

```sql
-- 啟用 RLS
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;

-- 匿名用戶政策
CREATE POLICY "anon_can_insert_orders"
  ON orders FOR INSERT TO anon WITH CHECK (true);

-- 認證用戶政策
CREATE POLICY "authenticated_can_insert_orders"
  ON orders FOR INSERT TO authenticated WITH CHECK (true);

CREATE POLICY "authenticated_can_select_orders"
  ON orders FOR SELECT TO authenticated USING (true);

CREATE POLICY "authenticated_can_update_orders"
  ON orders FOR UPDATE TO authenticated USING (true);

CREATE POLICY "anon_can_select_own_order"
  ON orders FOR SELECT TO anon USING (true);
```

**驗證**
- ✅ 匿名用戶可插入訂單
- ✅ 認證用戶可讀取/更新訂單
- ✅ 管理後台正常運作

**相關提交**

## 🔧 技術細節

### RLS (Row Level Security) 概念

**何謂 RLS?**
- Supabase 的行級安全機制
- 控制不同用戶對數據的存取權限
- 分為: SELECT, INSERT, UPDATE, DELETE

**本次修復的政策**

| 政策名稱 | 對象 | 操作 | 權限 |
|--------|------|-----|-----|
| anon_can_insert_orders | 匿名用戶 | INSERT | ✅ 允許 |
| authenticated_can_insert_orders | 認證用戶 | INSERT | ✅ 允許 |
| authenticated_can_select_orders | 認證用戶 | SELECT | ✅ 允許 |
| authenticated_can_update_orders | 認證用戶 | UPDATE | ✅ 允許 |
| anon_can_select_own_order | 匿名用戶 | SELECT | ✅ 允許 |
