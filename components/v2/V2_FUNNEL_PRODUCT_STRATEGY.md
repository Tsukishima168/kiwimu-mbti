## 1. 三層產品的正式分工

| 產品 | URL | 角色 | 使用者得到什麼 |
|---|---|---|---|
| **V1** | `/` | 信任層 | 我先被完整理解一次，並開始留下紀錄 |
| **V1.5** | `/explore` | 擴散層 | 我可以快速投射、分享、拿到角色感與社群貨幣 |
| **V2** | `/read` | 升級層 | 我不只知道自己是哪一型，我可以解鎖更完整的 A/T、維度、原型與收束提問 |

不要把三者做成互相吃掉的關係。

- `V1` 不是舊版，要保留
- `V1.5` 不是 V2 teaser，它是擴散用的獨立入口
- `V2` 才是付費產品，但它要站在 `V1` 已有的登入 / 累積能力上

## 2. 漏斗應該怎麼設計

### 真實漏斗（產品版）

```text
社群 / SEO
  ├─→ V1 (/)
  │     ├─ 免費完整 MBTI 體驗
  │     ├─ login unlock
  │     └─ 累積 test runs / archive
  │
  ├─→ V1.5 (/explore)
  │     ├─ 快速角色投射
  │     ├─ 社群分享
  │     └─ 軟導向 V1 / V2
  │
  └─→ V2 (/read) [公開第一版]
        ├─ 試讀免費層
        ├─ Paywall
        └─ 解鎖完整 MBTI 深度報告
```

### 正式定義

#### V1 的任務

- 建立信任
- 先讓使用者覺得「這個站不是亂寫的」
- 建立登入與累積紀錄基礎

#### V1.5 的任務

- 擴散
- 情緒投射
- 讓更多人用更低成本接觸 Kiwimu

#### V2 的任務

- 把一次測驗升級成值得付費讀完的 MBTI 深度報告
- 把 A/T、四維度、人物原型、帶走這個做成付費價值
- 完成第一次真正的付費升級

## 3. NT$149 到底在賣什麼

不是只賣內容深度，也不是只賣 90 天券。

正式商品定義：

> **NT$149 = 解鎖這份完整 V2 MBTI 深度報告。**

這句話很重要，因為它把兩種價值接在一起：

- **A｜首購鉤子**
  這份報告本身夠深、夠準、夠值得解鎖

- **B｜LTV / 回訪引擎**
  我之後回來，不只是再測一次，而是能看到自己跟上次有什麼不同

一句話：

> A 負責成交，B 負責續命。

---

## 4. 為什麼不能只賣 A，也不能只賣 B

### 只賣 A：完整深度報告

問題：

- 容易一次性消耗
- 用戶讀完就結束
- LTV 太薄

### 只賣 B：90 天變化軌跡

問題：

- 第一次付款時還沒有上一筆可比
- 價值太晚發生
- 首購鉤子不夠強

### 正解：A + B

- 頁面前台用 A 說服
- entitlement promise 用 B 收口

這不是兩個商品，而是一個商品的兩段價值。

## 5. V2 頁面的商業任務

V2 頁面不是在「完整介紹理論」，它要完成三件事：

### 1. 命中

第一屏就讓使用者覺得：

> 這真的在說我最近的狀態。

### 2. 抬升

讓使用者覺得：

> 我這樣不是只是有問題，而是有一套有代價的能力。

### 3. 承諾

讓使用者覺得：

> 我今天解鎖的不只是多一點字，而是一份會記住我、之後還能回來看的東西。

## 6. V2 IA 該怎麼預留「變化」但不破壞首購

第一次測的人沒有 timeline 可以看，所以 timeline 不能搶主畫面。

### 正確做法

#### Layer 0｜Header Context

很輕地顯示：

- `第 1 次顯影`
- 或 `距離上次 18 天`

第一次用戶看到的是「這是你的第 1 次」。
第二次之後才會有對比感。

#### Layer 1–6｜主報告

照 `V2_REPORT_ARCHITECTURE.md` 的主體六層走。
第一次成交靠這裡，不靠 timeline。

#### Layer 7｜Change Promise / Timeline Slot

放在 Paywall 附近或 Soul Reflection 後，內容是：

- 解鎖後，這份報告會被保存
- 90 天內重測可看見變化
- 下次不只是拿到新結果，而是看到「你從上次到現在改了什麼」

### 規則

- 第一次體驗：看到的是 promise
- 第二次體驗：才看到 compare

## 7. V2 報告裡，哪些是首購價值，哪些是回訪價值

### 首購價值（第一次也成立）

- 狀態命名
- Anchor Fragments
- Protective Pattern
- Life Spillover
- Resonance Coordinates
- Soul Reflection
- 顯影等級 / 狀態切面 / 真實原型 / 狀態用途

### 回訪價值（第二次之後才成立）

- 這次 vs 上次的狀態差異
- Trait / 維度變化摘要
- 「你從上次到現在變了什麼」的敘事
- N 次測驗的個人 timeline

這兩層不能混淆。

## 8. 現在真正要做的，不是 UI，而是這四個決策

### D1. 商品句

把這句定死：

> NT$149 = 解鎖這份完整報告 + 90 天內回來看自己怎麼變。

### D2. V2 入口

決定 V1 / V1.5 到 V2 的軟 CTA 怎麼長。

### D3. Paywall promise

決定 Paywall 寫的是：

- 你會多看到什麼深度
- 以及你之後還會得到什麼

### D4. 首次 / 回訪雙狀態 UI

同一頁面要能處理：

- 第一次：只有 promise
- 第二次：真的有 compare data

## 9. 實作優先順序

```text
1. 定商品句
2. 定 V2 paywall promise
3. 定 V1 / V1.5 → V2 的軟 CTA
4. 在 V2 IA 補 Layer 0 / Layer 7
5. 做 checkout + entitlement
6. 做 timeline compare MVP
```

## 10. 不要再重複討論的結論

- `V1` 不是純免費舊產品，它已經有 login / archive / runs 基礎
- `V2` 不是從零開始做「連續性」，而是把既有紀錄升級成變化敘事
- `NT$149` 不該只賣更多內容，也不該只賣未來功能
- 正解是：**完整報告 + 90 天變化視窗**
- 首購靠深度，留存靠連續性
