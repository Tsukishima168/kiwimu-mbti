# 產品路線圖（測驗平台）

本文件記錄測驗產品的演進方向：既有 MBTI 的深化，以及新測驗類型「天賦原動力」的規劃。與訂閱／買斷商模、多測驗擴充一致。

---

## 一、現狀

- **靈魂甜點 MBTI**：現行 40 題、16 型＋A/T 變體、結果含甜點配對與月島整合。
- 先上線測試，再導入訂閱或買斷；未來會新增 MBTI 以外的測驗類型。

---

## 二、MBTI 測驗的進化

- **方向**：從現行版本演進為 **更深度的 MBTI 測驗**。
- **可能內涵**（依實際產品決策調整）：
  - 題數或題組增加（例如分階段、進階題）。
  - 維度解讀更細（子維度、百分比、情境描述）。
  - 結果內容深化：職涯／關係／成長建議更個人化，或與甜點／月島情境更緊密。
  - 報告形式升級：可下載的完整報告、對比歷史結果等。
- **技術預留**：  
  - 將現行測驗視為 `mbti` 的某一「版本」或「深度」（例如 `mbti_basic` / `mbti_advanced`），之後同一類型下可並存多個版本，依權限或付費解鎖。

---

## 三、新測驗類型：天賦原動力

- **定位**：與 MBTI 並行的 **第二種測驗類型**，主題為天賦／內在驅力。
- **產品面**：  
  - 題型、計分邏輯、結果結構與 MBTI 不同，需獨立設計（題庫、維度、結果文案與圖像）。  
  - 可與 MBTI 形成「測驗矩陣」：同一用戶可做多種測驗，結果可並存、對照或整合（例如月島／訂閱權限）。
- **商模**：  
  - 可採「單測驗買斷」或「訂閱解鎖全部測驗（含 MBTI 進階＋天賦原動力）」等，與既有訂閱／買斷規劃一致。
- **技術預留**：  
  - 測驗類型抽象化：例如 `quiz_type = 'mbti' | 'talent_drive'`（或你之後訂的名稱）。  
  - 題目、計分、結果 API／資料表依 `quiz_type` 分流，前端依類型載入對應流程與版型。  
  - 權限與付費邏輯以「測驗類型」（及必要時的「版本」）為單位，方便未來再擴第三、第四種測驗。

## 四、遊戲化／月活與付費（像玩遊戲一樣）

整體方向：**每月有活動、有高級會員、有讓人想付費的虛擬商品或抽獎**，讓使用體驗像在玩遊戲、有持續回來的理由。

### 4.1 每月活動

- 每個月有主題活動（例如節慶、新測驗、限定結果、合作甜點等）。
- 活動期間可搭配：限定測驗、限定結果樣式、任務、獎勵、高級會員專屬內容等。
- **技術預留**：活動可視為「期間限定內容」或「活動 ID」，與測驗類型、權限、虛擬商品綁定。

### 4.2 高級會員（月訂閱）

- **每月可購買的高級會員**：解鎖當月／長期權益（例如進階測驗、完整報告、限定樣式、活動優先、虛擬商品折扣等）。
- 訂閱制可與「月活動」綁定：例如當月會員專屬活動、當月限定獎勵，形成「每月都有新東西」的節奏。
- **技術預留**：會員狀態（是否訂閱、到期日、方案）需有儲存與檢查點；可與現有 Firestore／Supabase 用戶資料整合。

### 4.3 虛擬商品

- 推出 **會讓人想付費的虛擬商品**：例如限定結果邊框、主題、頭像裝飾、報告樣式、專屬稱號等。
- 可與測驗結果、分享圖、檔案館展示結合，增加「擁有感」與分享動機。
- **技術預留**：需「用戶擁有的虛擬商品」清單與「商品定義」（ID、類型、綁定位置）；付費完成後寫入用戶資料。

### 4.4 抽獎／扭蛋式機制

- **抽某種東西**：例如抽限定結果樣式、虛擬商品、優惠券、實體甜點兌換等。
- 可設計為：免費次數（登入／完成測驗／月活動任務）＋付費加抽，兼顧留存與變現。
- **法規注意**：若涉及「抽獎」「機率」，需符合當地博奕／獎品相關法規與揭露機率；虛擬為主、實體為輔時也建議先釐清規範。
- **技術預留**：獎池定義、機率、已抽紀錄、次數（免費／付費）需可儲存與查詢。

### 4.5 Discord 的角色（所以才要結合 Discord）

- **身份即玩法**：測驗完成 → 取得 Discord 身份組（16 型／象限）→ 進入對應頻道，**身份從測驗延續到社群**，像遊戲裡的「職業」或「陣營」。
- **月活動的據點**：每月活動公告、限定任務、高級會員專屬頻道、抽獎／虛擬商品發放，都可集中在 Discord；**Discord 就是「大廳」或「公會」**，讓「像玩遊戲」有實際的聚集地。
- **未來遊戲的入口**：若推出 MBTI 主題遊戲，Discord 可作為組隊、公告、活動報名、發放獎勵的管道；**測驗 → Discord → 遊戲** 形成一條龍。
- **技術預留**：現有 Discord 身份組綁定、邀請連結、驗證流程可沿用；未來遊戲或月活動可透過 Bot 發放角色、任務、虛擬商品編碼或連結。

### 4.6 小結

| 元素 | 說明 |
|------|------|
| 月活動 | 每月主題、限定內容、任務與獎勵，拉回訪與參與 |
| 高級會員 | 月訂閱，解鎖進階內容與當月權益 |
| 虛擬商品 | 付費購買的裝飾、樣式、稱號等，增加擁有感與付費動機 |
| 抽獎／扭蛋 | 免費次數＋付費加抽，注意法規與機率揭露 |
| **Discord** | 身份延續、月活動據點、未來遊戲入口與社群大廳 |

## 五、長期願景 — 屬於 MBTI 的遊戲

方向：**未來想設計一款「屬於 MBTI」的遊戲**，讓測驗不只在網頁結束，而是延續成可玩、可互動、可與同型／異型一起體驗的世界。以下擴張想法，供之後收斂規格用。

### 5.1 為什麼「MBTI 遊戲」有趣

- **16 型自帶角色感**：每型有性格、優勢、盲點、甜點配對，可直接轉成遊戲中的「角色」「職業」或「陣營」，不需從零建世界觀。
- **測驗即創角**：用戶做完測驗就「創角」完成，降低進入門檻；重測可視為「轉職」或「第二角色」。
- **社群即內容**：同型頻道、象限對戰、跨型組隊，Discord 裡的身份與關係可直接成為遊戲內的社交層。
- **月活動即賽季**：每月活動可等同遊戲的「賽季」「限時副本」或「劇情章節」，高級會員／虛擬商品／抽獎都可與遊戲內獎勵打通。

### 5.2 遊戲類型可延伸的方向（擴張想法）

| 方向 | 簡述 | 與 MBTI／現有產品的連結 |
|------|------|---------------------------|
| **敘事／選擇型** | 劇情分支、對話選擇，不同選擇導向不同結局；**MBTI 影響推薦選項或隱藏路線**。 | 測驗結果 = 角色初始設定；靈魂甜點／月島可成劇情場景或獎勵。 |
| **派對／卡牌型** | 16 型當作卡牌或角色，技能與性格掛鉤；對戰或合作闖關。 | 同型組隊、象限對抗；Discord 組隊、月活動賽季。 |
| **協作任務型** | 依象限或類型組隊解任務，需「不同型」分工（例如 N 想點子、S 執行、J 排程）。 | 強調類型差異即玩法；天賦原動力可成「第二職業」或加成。 |
| **輕競技／配對型** | 依類型配對（同型／異型／象限），競技或合作；類型影響能力加成或策略。 | 虛擬商品可為外觀／稱號；抽獎可出限定角色皮膚或技能。 |
| **經營／養成型** | 以「靈魂甜點店」「月島」為背景，依類型經營不同風格、解鎖不同甜點與劇情。 | 與現有甜點配對、月島整合高度一致；高級會員可解鎖地圖或角色。 |

以上可單做一種，也可先做「小遊戲」（例如每月限時小活動）再演進成常駐產品。

### 5.3 與現有產品的串接

- **測驗**：測驗結果 = 遊戲內角色類型；進階 MBTI、天賦原動力 = 更多維度或第二職業。
- **Discord**：身份組 = 遊戲內陣營／公會；頻道 = 組隊、公告、發獎；Bot = 報名活動、查詢角色、發放虛擬商品。
- **月活動／高級會員／虛擬商品／抽獎**：活動可為「遊戲內限時副本」；會員解鎖遊戲內關卡或外觀；虛擬商品可同時用在網頁結果頁與遊戲內；抽獎可出遊戲內道具或網頁限定樣式。
- **月島／甜點**：遊戲內可出現「月島」場景、甜點任務、實體兌換；形成 **測驗 → Discord → 遊戲 → 線下** 的閉環。

### 5.4 小結

- **短期**：測驗 + Discord 身份 + 月活動 + 高級會員 + 虛擬商品／抽獎，先把「像玩遊戲」的節奏與付費跑通。
- **中期**：可做「限時小遊戲」或輕量互動（例如每月問答、型別對戰小活動），試水溫。
- **長期**：推出一款常駐的 **MBTI 主題遊戲**（敘事／派對／協作／經營等擇一或融合），與測驗、Discord、月活動、虛擬商品深度綁定。

此節會隨產品決策更新；具體遊戲類型、平台（Web／App／Discord 內）、技術選型可另開規格檔。

## 七、技術與文件對應

- **多測驗／多版本**：見本文件第二、三節的「技術預留」。  
- **資料與事件**：新測驗類型仍可沿用 GA4 / Firestore 的 `quiz_complete`、`result_view` 等，以 `quiz_type` 或 `quiz_version` 區分。  
- **Supabase**：天賦原動力可另建題目表／結果表（或共用 schema 加 `quiz_type`），與 MBTI 內容分離或共用專案皆可，依規模再定。  
- **Discord**：現有身份組綁定與 Bot 可作為月活動、未來遊戲發獎與組隊的基礎。  
- **遊戲**：若推進 MBTI 遊戲，需另定平台（Web／App／Discord）、技術棧與與測驗／會員／虛擬商品的 API 串接。

此路線圖會隨實際產品決策更新；MBTI 深化、天賦原動力、月活動、虛擬商品／抽獎、Discord 與 MBTI 遊戲的具體規格可在本文件或另開規格檔補上。
